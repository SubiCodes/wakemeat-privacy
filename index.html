Privacy Policy

Effective Date: June 2026 | Last Updated: June 2026

Wake Me At ("we," "our," or "us") provides the Wake Me At mobile application. We are deeply committed to maintaining clear, strict, and absolute privacy safeguards regarding your mobile device data. This document outlines our offline-first data architecture and internet usage clarity.

Strict Network Boundary & Offline Operation: Wake Me At operates entirely offline. The application does NOT use or maintain any application servers, user management APIs, database cloud syncs, or remote analytics platforms. The only operational requirement for network communication is fetching visual map layers via our mapping layout toolkit.

1. Internet & Map Tile Data Footprint

The application requests network access strictly to stream interactive interface visuals:

  • Map Interface Interaction: When viewing the tracking view or configuring coordinates, the app utilizes the device's internet connection solely to download underlying map layout configurations and regional tiles.
  • No Payload Transmission: Your designated destinations, coordinates, radius choices, and telemetry data are never attached to these requests. The internet stream is exclusively a one-way download of terrain graphics.

2. Background Location Scope

Wake Me At is a proximity arrival companion built to trigger high-priority alerts when entering safety circles.

  • Background Execution: To trigger alerts when your device screen is off or another app is active, the app requires location access in the background. This background monitoring uses the device's native low-power hardware geofencing processors.
  • On-Device Calculations: 100% of location matching, proximity math, coordinate testing, and task orchestration runs locally on the device's thread via expo-location. Absolutely zero real-time coordinates leave the sandbox or stream to public servers.

3. Local Storage Sandboxing

All application memory remains inside the localized execution directory:

  • Data Isolation: Custom locations, configured radii, and active target statuses are serialized directly into an on-device local instances storage model powered by a secure, compiled MMKV key-value cache layer (wake-me-at-storage).
  • Inter-process Communication: Ephemeral state transfers between active background listener threads and the user interface happen inside localized device runtime buffers.

4. Third-Party Kits & SDK Boundaries

Our client interface utilizes specific developer-vetted SDK architectures to display interface elements. These libraries handle data as described below:

  • Mapbox SDK (@rnmapbox/maps): Handles rendering interactive base maps. Mapbox processes standard telemetry metrics and IP endpoints strictly to authorize, rate-limit, and deliver graphic map tiles under their baseline privacy provisions.
  • Notifee SDK: Used to render critical alerts, audio actions, and status updates locally on the device. Notifee functions completely offline.

5. Children's Privacy

Wake Me At is explicitly designed as a general utility tool. It does not target, collect, or address personal identifier footprints from individuals under thirteen (13) years of age. Because the application uses an offline-first configuration with zero network storage, no children's tracking parameters can be gathered or sent to third parties.
